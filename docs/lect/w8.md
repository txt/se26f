## 1. Glossary

### 1.1 Process: the shape of the work

- **Process.** The rules a team lives by. Estimation models weigh
  four things: the **product** (what you build), the **personnel**
  (who builds it), the **platform** (what you build on), and the
  **process** (how you coordinate). A classic process failure: nobody
  owns the interfaces, so no one is watching how things move across
  seams.
- **Waterfall.** A one-way sequence — requirements → design →
  implementation → testing → maintenance — with no paddling back up
  the falls. Documentation-heavy; suited to large government/military
  contracts where money is released per completed stage, and to
  hardware/software co-design (Huawei: "the hardware is ready in four
  months, so the software must be"). Born in an era of slow compiles,
  when you *thought* before you ran the compiler and went for coffee
  while it ran.
- **Agile / Scrum.** A cyclic process. A **backlog** of requirements;
  each **sprint** (a day, a week, a month) you pick the items of
  highest value and lowest cost to build next, build them, then
  re-prioritize. The **daily scrum** is short — nobody sits down —
  and asks three questions: what did you do, what are you doing, what
  are your roadblocks. Requirements are *not* fixed; some may never
  be built. The 2001 **Agile Manifesto** (Snowbird) valued
  individuals and interactions over processes and tools, working
  software over documentation, customer collaboration over contract
  negotiation, responding to change over following a plan.
- **The swing.** Agile was the swing away from top-down control
  toward distributed units — until ~2008 Google had "meetings to
  decide when to have meetings." Then a swing partly back. No method
  is best: short cycles suit fast-changing requirements and eager
  customers (and build reputation for open-source teams); long cycles
  suit safety-critical or fixed requirements.
- **Agile-fall.** A real hybrid (sometimes a joke, sometimes a
  business model): advertise "agile" to recruit, then run mostly
  waterfall because the industry — safety-critical, payment
  milestones — demands it. Before mocking a local deviation from the
  textbook, ask what **politics, money, and risk** made it sensible.

### 1.2 Config management: the discipline that separates teams

- **Configuration management.** What sophisticated teams do very well
  and small teams do very badly. Not just source code — the config
  files that control linters, editors, CI, and cloud services belong
  under version control too.
- **Git Flow vs commit-to-main.** Git Flow: a master branch,
  long-lived feature branches, work that wanders off for weeks and
  returns — right for loosely connected teams of near-strangers
  getting occasional updates (think Microsoft Word's spell-check team
  going away for months). Its failure mode: a jungle of branches
  nobody can explain. **Commit-to-main** (trunk-based): one mono-repo
  is production; everyone commits back to main — but you branch a
  daily copy, practice committing there first, and only promote to
  main when a wall of tests and static checkers stays silent. It
  fails when builds are flaky, merges are rare, or people fear
  pulling from main. You do not let beginners commit to main (unless
  you are old Facebook: "move fast and break things" — fine for a
  night-out messaging app, not fine once Facebook is someone's
  emergency-services channel).
- **CI / CD / CD.** **Continuous integration** — every push triggers
  the full build and test. **Continuous delivery** — the code is
  always *ready* to ship at the press of a button. **Continuous
  deployment** — there is no button; commit to main and the world
  sees it.
- **Hooks and badges.** A GitHub workflow (`.github/workflows`, in
  YAML — "yet another markup language") runs your tests on push. The
  result becomes a **badge** in your README — and a badge that only
  smiles back when clicked is dead; a live badge links to the actual
  service. Pre-commit / pre-push hooks run tests *locally before* you
  inflict code on teammates.
- **The pipeline is software too.** Version it. A shared `.pylintrc`
  (or formatter config) encodes the team's agreed conventions — which
  violations are OK (trailing whitespace, two statements per line) —
  and lives in the repo. Editor config files carry more than colors:
  which checks are on, which previews work. Shared tool config is how
  a team gets **zero internal boundaries**.
- **Micro pull requests.** Senior engineers spend more time reviewing
  than writing. A reviewable PR is roughly ±50 lines; 2000 lines
  cannot be reviewed. Hence "stacks of PRs are stacks of promises" —
  a whole emerging language of small, layered changes.

### 1.3 Language comparison: one idea, many tongues

- **Three axes.** Languages differ in **dispatch** (how the machine
  finds the code to run), **checking** (how much verification happens
  at runtime vs compile time), and **control** (whether data
  structures are inert or carry their own control).
- **Dispatch via dunders / metamethods.** Python customizes behavior
  with **dunder** methods (`__init__`, `__repr__`, `__add__`,
  `__eq__`, `__len__`, `__call__`, `__missing__`). `w1 + w2`
  *desugars* to "find `w1`'s type, look up `__add__`, call it with
  `w1` and `w2`." Lua ships with almost nothing ("batteries not
  included") but hands you **metatables**: point a table's `__index`
  at itself and a whole object system — polymorphism, inheritance —
  falls out of a few primitives.
- **Single vs multiple dispatch.** Normal OO dispatches on *one*
  type — the receiver. **Multiple dispatch** (Julia, CLOS) picks the
  method from *all* argument types: `collide(asteroid, ship)` differs
  from `collide(ship, asteroid)`. This is what makes Julia's culture
  of wiring math packages together with type-tuned bridges feel
  natural.
- **The typing ladder.** **JavaScript** — trust the programmer, get
  surprised at runtime (every function is a lambda body written into
  a named location). **TypeScript** — the same code annotated; some
  checking at compile time. **Rust** — makes the illegal
  unrepresentable: it refuses to compile until a class of errors is
  provably gone. "Working with Rust is a fight with the compiler, and
  when the compiler finishes, certain properties are guaranteed."
- **Type inference as a ripple.** Mark one literal's type and the
  knowledge spreads: `d = 1 + 1` makes `d` an int, which ripples to
  everything `d` touches; where a string-ripple meets a number-ripple
  and the operation is invalid, that is a compile-time error caught
  before any run.
- **Control outliers.** Prolog — state facts and rules, let the
  machine search. Smalltalk — everything is a message send.
- **Minimalism and DSLs.** awk wins by doing one small thing;
  domain-specific languages trade generality for fit (the "elbow
  test"). The reflected-dunder trick builds a pipe-style internal DSL
  in ten lines by hacking `__ror__` (the `|` operator) and
  `__call__`.

## 2. Said in class, not in the notes

### 2.1 Richard Hipp and SQLite: the anti-LLM hero

SQLite is the most-deployed database on Earth — every phone, every
Linux box, the Mars rovers. Richard Hipp built *everything* himself
(his own editor, web server, database) rather than grab free
packages. Had he done the LLM move — "grab Berkeley DB, it's free" —
SQLite would have been sunk when Oracle later bought Berkeley DB and
put it behind a paywall. Building his own kept the most-deployed
database on the planet free. The moral: grabbing packages fast is how
you ship debt and inherit someone else's licensing fate.

### 2.2 Closures hold code, and desugaring makes it trivial

A **closure** holds all variables live at its creation — and can hold
code as well as data. Hack `__add__`/`__repr__` (Python) or
`__add`/`__tostring` (Lua) and two wallets add and print themselves;
`w1 + w2` desugars to type-lookup-then-call. Hack `__ror__` and
`__call__` and plain Python starts to read like a Haskell pipeline.
The recurring wonder of the lecture: machinery that *sounds*
impossibly complex — polymorphism, your own object system, a pipe
language — is "trivial once you get down to a desugared language."

## 3. Review questions

Exam-style: **(a)** recall, **(b)** synthesis. (Mid-term format; the
real exam reaches "down to Rust.")

**1. Waterfall vs agile.**
(a) List the waterfall stages in order, and give the three questions
asked at a daily scrum.
(b) Huawei told the lecturer to "forget this agile rubbish." Explain
why hardware/software co-design pushes a team toward waterfall, and
describe how a cloud team can run a *one-day* waterfall and still be
effectively agile.

**2. The Agile Manifesto.**
(a) State the four "X over Y" values of the 2001 Agile Manifesto.
(b) By 2008 Google had "meetings to decide when to have meetings."
Explain what over-applying agile costs, and name one situation where
you would deliberately choose long cycles over short ones.

**3. Branching strategies.**
(a) Distinguish Git Flow from commit-to-main: what moves where, and
who is each one for?
(b) Your four-person team commits straight to main and builds are
breaking daily. Give two signals that commit-to-main is failing you,
and the specific machinery (branches, hooks, checks) that would make
either strategy safe.

**4. CI/CD and badges.**
(a) Distinguish continuous integration, delivery, and deployment, and
say what a README badge must link to in order to be "live."
(b) A teammate wants auto-format-on-save with no shared config. Using
the "newbie reformats 2000 lines" story, explain the review damage,
and state the config-management fix that keeps formatting from
polluting diffs.

**5. Process follows politics.**
(a) Define "agile-fall" and give one legitimate reason a team runs
it.
(b) "Before you mock a local method, consider the local politics,
money, and risk." Apply this to a team forced to write documentation
for version *i−1* while coding version *i*. Why does the deliverable
exist, and what does that tell you about reading any process rule?

**6. Dispatch.**
(a) What does `w1 + w2` desugar to in Python, step by step? Name the
dunder involved.
(b) Lua ships without inheritance or polymorphism, yet you can build
an object system in it. Explain the one metatable mechanism that
makes this possible, and connect it to the course's claim that
"complex machinery is trivial in a desugared language."

**7. Single vs multiple dispatch.**
(a) Define single dispatch and multiple dispatch.
(b) In a space game, `collide(asteroid, ship)` must differ from
`collide(ship, asteroid)`. Show why single dispatch makes this
awkward and multiple dispatch makes it natural, and say why Julia's
package ecosystem benefits.

**8. The typing ladder.**
(a) Place JavaScript, TypeScript, and Rust on the checking axis: what
does each do when you pass the wrong type?
(b) Explain type inference as a "ripple" spreading from a literal.
Where does the ripple detect an error, and what does "make the
illegal unrepresentable" buy Rust that a runtime check cannot?

**9. Closures and desugaring.**
(a) What does a closure hold, and what does `w1 + w2` desugar to in
Python?
(b) The lecture's recurring claim is that machinery which *sounds*
complex — your own object system, a pipe language — is trivial once
a language is desugared. Back the claim with two examples from the
language lecture (one dispatch, one operator hack), naming the dunder
or metamethod each one leans on.

**10. Dependencies and control.**
(a) Name one thing SQLite's author built himself rather than grab as
a free package.
(b) SQLite's author refused to grab Berkeley DB; an LLM would have
grabbed it. Tell the story and extract the general rule about speed,
dependencies, and who controls your fate.

## 4. Answers, briefly

**A1.** (a) Requirements → design → implementation → testing →
maintenance; scrum questions: what did you do, what are you doing,
what are your roadblocks. (b) Co-design locks a date: the hardware
arrives in four months and the software must match it, so you need
upfront requirements and a fixed plan — waterfall. A cloud team runs
A/B/C/D (plan/design/build/test) in a single day because deploying is
one install away, then changes its mind tomorrow — fast waterfalls
that add up to agility.

**A2.** (a) Individuals/interactions over processes/tools; working
software over documentation; customer collaboration over contract
negotiation; responding to change over following a plan. (b) Process
overhead compounds until coordination costs more than the work;
choose long cycles when requirements are fixed or the system is
safety-critical and must be checked heavily before release.

**A3.** (a) Git Flow: long feature branches off master, work returns
after weeks — for loosely connected near-strangers. Commit-to-main:
one production mono-repo everyone commits back to — for fast teams
with aggressive, trusted test pipelines. (b) Failing signals: flaky
builds break on every merge; people are afraid to pull from main (add
rare-merge pushback as a third). Safety machinery: a daily working
branch you promote only after local tests + static checkers pass,
pre-push hooks, and branch protection requiring review.

**A4.** (a) CI = every push builds and tests; CD(delivery) = always
ready to ship at a button; CD(deployment) = commit to main ships to
the world, no button. A live badge links to the real CI service, not
a static icon. (b) Format-on-save with no shared config rewrites
every file the newbie opens, burying real changes under thousands of
reformatted lines nobody can review. Fix: a shared formatter/linter
config in the repo (`.pylintrc` or equivalent) so everyone formats
identically and diffs stay meaningful.

**A5.** (a) Agile-fall: advertise agile to recruit, run mostly
waterfall because the domain demands it; legitimate when payment
milestones or safety requirements force staged, documented delivery.
(b) The version-*i−1* document exists because accountants release
money on deliverables, not because it documents current truth — so
some process artifacts serve funding/politics, not engineering. The
lesson: read a process rule by asking what politics, money, and risk
produced it before judging it.

**A6.** (a) `w1 + w2` → find the type of `w1` → look up `__add__` on
that type → call it with `w1` and `w2`. (b) Point a table's
`__index` metamethod at itself (or a parent): a message the table
doesn't understand is looked up there, which yields method lookup,
inheritance, and polymorphism from one primitive — complex OO
machinery, trivial once the language is desugared to lookup-and-call.

**A7.** (a) Single dispatch selects the method from one type (the
receiver); multiple dispatch selects from all argument types. (b)
With single dispatch, `asteroid.collide(ship)` privileges the
asteroid and you hand-code the ship case inside it (and duplicate for
the reverse); multiple dispatch defines `collide(Asteroid, Ship)` and
`collide(Ship, Asteroid)` directly. Julia's community writes
type-tuned bridges between math packages, which is exactly
dispatch-on-all-types.

**A8.** (a) JavaScript: accepts it, surprises you at runtime.
TypeScript: annotates and catches some mismatches at compile time.
Rust: refuses to compile until the error class is provably gone. (b)
Mark one literal's type; the knowledge ripples through every
expression it touches; an error appears where a string-ripple meets a
number-ripple in an invalid operation — before any run. "Make the
illegal unrepresentable" means whole classes of runtime type errors
cannot occur in a compiled Rust program, which a runtime check can
only catch *after* it happens.

**A9.** (a) A closure holds every variable live where it was created,
and can hold code as well as data; `w1 + w2` desugars to "find
`w1`'s type, look up `__add__`, call it with `w1` and `w2`." (b)
Dispatch: hack `__add__`/`__repr__` (Python) or point Lua's
`__index` metatable at a parent and a full object system —
polymorphism, inheritance — falls out of lookup-and-call. Operator
hack: define `__ror__` (the `|` operator) and `__call__` and plain
Python reads like a Haskell pipeline. Both show complex-sounding
machinery reducing to a few desugared primitives.

**A10.** (a) Any of: his own editor, his own web server, his own
database engine. (b) Richard Hipp built his own everything rather
than grab Berkeley DB; when Oracle later paywalled Berkeley DB,
SQLite — the most-deployed database on Earth and Mars — stayed free
because it had no such dependency. Rule: grabbing packages fast buys
speed but mortgages control of your dependencies and their future
licensing.
