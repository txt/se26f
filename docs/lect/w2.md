## Glossary

- **use case**: one actor chasing one goal, numbered steps; happy
  path clean, all branching in the **extensions** (where the real
  requirements hide).
- **oracle / oracle problem**: the thing that says what "correct"
  means. Running is easy; asserting is hard. No oracle, no test —
  just a run.
- **mutation testing**: plant a small deliberate bug (a mutant);
  a suite that cannot kill it is a weak suite. An oracle for your
  *tests*.
- **differential testing**: feed one input to several independent
  implementations (five SQL engines); the odd one out fails. An
  oracle from redundancy.
- **metamorphic testing**: when the exact answer is unknowable,
  assert a relation between runs: adding a conjunct to a query
  can only shrink the result set.
- **property-based testing**: invariants over random inputs
  (sorted output is ordered; save-then-load round-trips).
- **equivalence class**: a set of inputs claimed to behave the
  same. Probed once it is a hypothesis; probed twice, a
  partition.
- **delta debugging**: shrink a failing input/config by repeated
  halving until the minimal failure remains.
- **ablation study**: remove one part at a time; if nothing gets
  worse, that part was not earning its keep.
- **compartmental model**: stocks (levels) joined by flows
  (rates); each tick, level += dt × (in − out). A graphical
  notation for a system of equations.
- **Brooks' Law**: adding staff to a late project makes it later
  — communication is n², newbies tax mentors, payoff comes only
  after maturation. Verdicts depend on the **horizon** (tmax).
- **tests vs studies**: tests finish in under a minute and run
  constantly; studies take hours and run overnight. Layer your
  suite so the slow never blocks the fast.
- **coverage**: which lines some test touched. A disjunction, not
  a flow — 100% coverage proves nothing about paths; it is a
  floor, not a target.
- **seed**: the number that makes "random" replayable. Reset it
  before every test; ship it with every bug report.
- **CI / workflow / exit code**: GitHub runs your one command on
  every push and reads back a single number: 0 green, else red.
  That number is all it knows.
- **commit vs push**: commit = local checkpoint (cheap, do it
  constantly); push = publish to the team (only after tests).
- **worktree**: one extra checkout per agent, so parallel work
  cannot clobber itself.
- **context window (and drift)**: the sliver of adjustable state
  on top of the model; recent text weighs more, so early goals
  fade unless you re-anchor them.
- **prompt vs loop**: a prompt is seconds and auditable; a loop
  is an overnight goal whose log nobody will ever read.
- **meta-prompting**: asking the model to write, tighten, or
  archive the prompt itself ("give me the prompts to do this
  again tomorrow").

## Said in class, not in the notes

1. **Tests vs studies.** Split the suite: sub-minute tests run in
   a loop while you type; hours-long studies run overnight. Once
   tests get slow, people stop running them — so protect the fast
   layer.
2. **Pre-commit beats post-commit.** A GitHub workflow is
   *post*-commit: it tells the team you broke things after you
   shared them. Run the same `make test` *before* you push. The
   workflow's exit code buys you a README badge: green shield,
   red shield — that is the whole interface.
3. **Differential testing** is a fifth way out of the oracle
   problem (beside LLM-as-oracle, mutation, metamorphic,
   fewer-tests): five database engines, one query — four agree,
   one is wrong. And remember the one-liner: "we'll put the
   night's transactions through it" is a run, not a test — no
   oracle of failure.
4. **Prompting extras.** (a) Set a role AND an audience: "you are
   a test engineer; the report is for my CTO"; personas generate
   tests ("Samantha has diminished vision and wants to ride the
   bus"). (b) The context-drift model: recent text is weighted
   more, so early requirements fade — re-anchor them. (c)
   Issue-stamping traceability: split bug reports into dated
   issues i1, i2...; stamp every code change with its issue;
   then "do not break old issues" becomes a promptable rule. (d)
   Prompts are seconds, loops are overnight — "submit your
   prompts" policies drown in loop logs. (e) A student's CRISP:
   Context, Role, Instruction, Structure, Progress. (f)
   Meta-prompting: end sessions with "what prompts would redo
   today's work?"
5. **Coverage, unpacked.** Coverage is a disjunction: test 1
   reached line 1 OR test 2 reached line 2 — nothing about the
   value that flowed between them. Reliability lives in paths,
   and all-paths is impossible, so reliability is statistical.
   Practical floor: 20–30% coverage is a red flag; 100% of weak
   asserts is still nothing.
6. **Delta debugging and ablation** are partition-and-probe in
   action: halve the failing config until the minimal failure
   remains; pull out one component at a time and see if anything
   worsens. Surviving every ablation does not prove optimal —
   it proves nothing is useless.
7. **Why commit ≠ push.** Local commits are checkpoints: botch
   an hour, check out yesterday, the stupidity is gone. Push
   only after the local suite runs — do not pollute the team.
   Automate the repeated thing (`make push` that asks "reason?"
   then commits, pushes, statuses). And the repgrid lesson
   transfers: cluster inputs by same-output regions, test each
   region once — that is equivalence partitioning discovered by
   clustering.
8. **The 68-truisms confession.** Your lecturer LLM-generated 68
   SE truisms as compartmental models and announced faster
   "LLM-based science" — then retracted a week later: many
   models were rubbish (100 people modeled as all-pairs
   communication; real projects use teams of ten). Moral: every
   generated line must face domain knowledge; a model no expert
   audited is a claim, not a finding.

## Ten questions (a = define, b = synthesize; ~10 min each)

**Q1 — oracles.** a) Define the oracle problem. b) "We test by
running the night's transactions through it." Why is that a run,
not a test? Give three oracles of different strengths for a
food-delivery ETA feature (an exact check, a relation, and a
floor).

**Q2 — metamorphic and differential.** a) Define both. b) A
4-conjunct SQL query returns 1000 rows. State the metamorphic
expectation for: adding a 5th conjunct; replacing a conjunct
with an OR; reordering conjuncts. When would differential
testing (five engines) catch what metamorphic cannot?

**Q3 — mutation.** a) What is a mutant, and what does "killed"
mean? b) `if x >= lo and x <= hi: accept()` with one test,
`x=5, lo=0, hi=10`. Give two mutants that survive this suite and
the tests that kill them. What does a surviving mutant tell you?

**Q4 — Brooks and the horizon.** a) In sd0's `rq()`, what are
y0, y1, and tmax? b) The verdict is "confirm" at tmax=30 and
"refute" at tmax=80. Has Brooks' Law been refuted? Design the
experiment that answers honestly (sweep, crossover point,
neutral band — and say why a single verdict cell is misleading).

**Q5 — seeds.** a) Why reset the seed before every test? b) A
loop runs 20 "repeats" with `srand(seed)` INSIDE the repeat
loop. What is the sd of those repeats? What do statistics on
them mean? Where does the reset belong, and what does
"reproducible ≠ deterministic" mean here?

**Q6 — coverage.** a) What does line coverage measure? b) Argue
both directions: why 100% coverage can still ship a broken
system (disjunction vs paths, weak asserts), AND why 25%
coverage is a red flag worth acting on.

**Q7 — shrinking the space.** a) Define equivalence class. b)
You must test a system with a million configs on a budget of 50
runs. Give a plan using partition-probe-twice, then delta
debugging when a config fails, then an ablation to justify each
system component. What can the ablation NOT prove?

**Q8 — CI.** a) What is the only thing GitHub's test workflow
knows about your tests? b) Write the minimal workflow yaml and
the `make test` rule it calls; say what line in a
roll-your-own test engine makes failures visible to it; explain
pre-commit vs post-commit checking and what the badge shows.

**Q9 — git for teams and agents.** a) Commit vs push: what does
each move, and where? b) Three coding agents work one checkout
overnight. What goes wrong? Fix it with worktrees; then explain
why local commits (recovery, test-before-push) and the
pull-request rule (no self-merge) still apply to agent output.

**Q10 — prompting.** a) Name four of the twenty prompting
heuristics. b) Rewrite this lazy prompt — "fix the bug in my
model" — applying at least six heuristics, including role +
audience and issue-stamped traceability. Then explain context
drift and how your rewrite anchors against it.

## Answers, briefly

**A1.** No stated "correct" → not a test. Transactions run has no
failure oracle. ETA: exact = known route fixture returns 14 min;
relation = adding traffic never shortens ETA (metamorphic);
floor = never crashes, never negative.
**A2.** 5th conjunct: ≤1000 rows. OR: ≥ the conjunct-only count.
Reorder: exactly 1000 (commutativity). Differential catches
wrong-but-relation-consistent answers — all metamorphic checks
can pass while every engine-specific count is wrong; a second
engine exposes it.
**A3.** Mutants: `>=`→`>` (x=lo untested); `and`→`or` (x=15
accepted). Kill with x=0 (expect accept) and x=15 (expect
reject). A survivor marks behavior your suite never constrains.
**A4.** y0 baseline score, y1 treatment score, tmax the horizon.
Not refuted — the claim is horizon-dependent: sweep tmax, report
the crossover (~71) and a neutral band for |gap| < eps; a single
cell is a photograph, not a law.
**A5.** sd = 0 — all repeats identical; statistics are fiction.
Reset belongs per-run (before each experimental unit), not
per-repeat. Reproducible = same seed replays; ≠ deterministic
across platforms unless you ship your own generator.
**A6.** Lines some test touched. 100%: coverage is line1 OR
line2, not the value flowing between them; weak asserts cover
without checking. 25%: three-quarters of the code has never
executed under ANY oracle — act on it.
**A7.** Same-signature inputs → one class; 2 probes per class
(disagreement splits the class); on failure, halve the config
until minimal; ablate parts one at a time. Ablation proves
nothing-is-useless, never optimality.
**A8.** One process exit code (0 green, else red). Seven-line
on:push yaml + `test: python3 test_brooks.py -all`;
`sys.exit(fails)` is the visibility line; workflows are
post-commit — run make test before pushing; the badge renders
the last exit code on the README.
**A9.** Commit: working dir → local repo. Push: local → remote.
Agents clobber shared files and each other's state; one worktree
per agent isolates them. Agent output merges like human output:
diff, local tests, then a PR someone else reviews.
**A10.** Any four (contract; artifacts verbatim; one task;
bounded diff; tests-first; assumptions; abstention; fixed
format; run-it-yourself; ...). Rewrite must show: role+audience,
paste code + failing trace verbatim, test-that-reproduces first,
diff bound, fixed output format, issue-stamp (i7, dated) on the
change. Drift: recent tokens outweigh early goals; the issue
list is the anchor you re-cite each turn.
